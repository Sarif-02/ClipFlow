# Connect ClipFlow to providers

Run `npm run build` and `npm start` from the project root. The launcher applies pending SQLite migrations and starts the web server and worker. Open `http://localhost:3001/integrations`, or use your configured `APP_URL`. Stop both with Ctrl+C. Restart ClipFlow if the worker exits. Use `npm run dev` while editing source. For a separate worker, `npm run worker` loads production environment files and `npm run worker -- --dev` loads development files. Use the intended database and keep both listeners on loopback.

If another process needs port 3001, set `APP_URL` to an unused localhost address such as `http://localhost:3002` in `.env.local`, restart, and browse to that address. Update Google’s redirect URI to the exact new value shown under Integrations. Instagram’s separate HTTPS callback still uses port 3443.

## YouTube

1. In [Google Cloud Console](https://console.cloud.google.com/apis/dashboard), create or select one project and enable YouTube Data API v3 and YouTube Analytics API.
2. Configure Google Auth Platform branding, audience and data access. Add your Google account to the test users if applicable. External Testing refresh tokens for these scopes can expire after seven days. See [Google OAuth](https://developers.google.com/identity/protocols/oauth2/web-server) and [token expiration](https://developers.google.com/identity/protocols/oauth2#expiration).
3. Create a Web application OAuth client. Add the exact redirect copied from Integrations. Default: `http://localhost:3001/api/oauth/youtube/callback`. The address you browse to must match `APP_URL`. Do not use an API key in place of OAuth.
4. Save the client ID and secret in Integrations, click Connect YouTube account, select the intended channel or Brand Account, and grant read, upload and analytics permissions. Repeat for each channel. Test Connection performs only authenticated reads.
5. Open Analytics and select a channel and range, then click Refresh. Google may delay daily reports. All channels compares individual channels; it does not pool unauthorized cross-owner totals or derive net growth. See [YouTube developer policies](https://developers.google.com/youtube/terms/developer-policies).
6. Check actual project upload limits in Google Cloud. ClipFlow defaults to 100 uploads per Pacific day but tracks only the calls it initiates. Adjust Integrations to match your project; [request an audit or extension](https://developers.google.com/youtube/data/guides/quota_and_compliance_audits) if necessary. Google defines eligible Shorts as square or vertical and up to three minutes under its [current guidance](https://support.google.com/youtube/answer/15424877); upload success is not a Shorts classification check.

Accounts shows the reported access token expiry, last refresh, and last successful provider request where recorded. Set the OAuth publishing status in Integrations to match the Google Cloud Audience page. External Testing generally gives these scopes seven day refresh tokens. To move out of Testing, review your declared scopes, branding, contact details, and audience in Google Cloud, choose Publish app on the Audience page, and use Verification Center to meet any applicable requirements. Reauthorize only accounts that need a new grant. See [app publishing and verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/overview) and [sensitive scope verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification).

Google removed the general private-only restriction for unverified upload projects on November 2, 2026. ClipFlow uses the chosen visibility and checks the returned status. Use Private for the first live test and obtain approval for that specific upload. [YouTube Data API revision history](https://developers.google.com/youtube/data/revision_history#november-2-2026)

Native scheduling is opt-in in YouTube configuration. For a public post more than 15 minutes in the future, the worker can upload it privately with `publishAt`. An accepted video stays in processing or awaiting provider until processed with the intended visibility. Other jobs use the local worker at the scheduled time.

## Instagram Reels

ClipFlow uses **Instagram API with Facebook Login for Business**, because [Meta restricts resumable local video uploads](https://developers.facebook.com/documentation/instagram-platform/content-publishing) to that login family. No public media hosting is used.

1. In the [Meta App Dashboard](https://developers.facebook.com/apps/), configure Instagram API publishing and Facebook Login for Business. Each Creator or Business account must be linked to a Facebook Page you can manage. Request `instagram_basic`, `instagram_content_publish`, `pages_show_list`, and `pages_read_engagement`. App roles and Page access govern eligible development accounts. Meta also lists `ads_management` and `ads_read` for the specific case of Page roles granted through Business Manager. For that case, add those permissions to the Login for Business configuration if required and obtain the applicable access. See [Meta’s publishing requirements](https://developers.facebook.com/documentation/instagram-platform/content-publishing).
2. Register `https://localhost:3443/api/oauth/instagram/callback`. Provide an already trusted localhost TLS certificate with a matching private key, set `META_TLS_CERT` and `META_TLS_KEY` to the files’ absolute paths in `.env.local`, and restart ClipFlow. For development retain `APP_URL=http://localhost:3001`. The added HTTPS listener accepts only the callback on loopback; there is no public tunnel or proxy to the dashboard. Do not disable TLS checks. If your Meta app configuration rejects a localhost HTTPS redirect or requires a public callback or data-deletion webhook, stop and request separate approval for a narrowly scoped solution.
3. Enter the Meta App ID, app secret, and supported API version (default v27.0). If the Meta product requires a Login configuration ID, set it as well and include the same publishing permissions in that configuration. Save and click Connect Instagram account. Approve only the intended linked Pages.
4. Check the Accounts page and Test Connection. ClipFlow exchanges the authorization code server-side and uses Page tokens for publishing. Reconnect when the grant expires or is revoked; it does not store or request your password. See [Meta’s manual OAuth flow](https://developers.facebook.com/documentation/facebook-login/guides/advanced/manual-flow) and [token lifecycle guide](https://developers.facebook.com/documentation/facebook-login/guides/access-tokens/get-long-lived).

No real OAuth or posting is part of automated verification. Live tests require separate approval. Start with a single video and one account on each platform. If a response is ambiguous, inspect the existing submission in the provider console. ClipFlow does not automatically start a duplicate upload.

## Gemini and local configuration

If Gemini is already verified, use its saved key and model. To configure a new project, create an API key in [Google AI Studio](https://aistudio.google.com/), paste it in Integrations, and select a supported model. Save and click Test connection to verify key and model access. Confirm the project uses the free tier in AI Studio before generating. ClipFlow keeps the saved model and makes standard requests. [Model access](https://aistudio.google.com/api-reference/models) · [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing)

In Step 3 of Create Post, add a description or transcript and select a style. Generate suggestions for one or several clips, review the text, apply the parts you want, and save your draft. Use Restore previous content to undo the latest application. The counters show locally tracked requests, including retries. Optional Analyze video sends a supported MP4 up to 8 MiB and 60 seconds only after confirmation. ClipFlow uses inline input and does not create a Gemini Files attachment. Google describes how it can use submitted material from unpaid services in the [Gemini terms](https://ai.google.dev/gemini-api/terms).

Template placeholders are `{{clip_name}}` for the display name, `{{source_title}}` for the original filename, `{{channel_name}}` for the destination account, `{{platform}}` for its platform, `{{context}}` for the entered description, and `{{date}}` for the date. Template fields that depend on the account become per-destination overrides. AI sends clip-level context and uses the selected template’s instructions. Presets can add an account group and apply metadata and the bulk interval. Review the destinations before confirming.

## AssemblyAI transcription

In **Integrations → AssemblyAI**, save an API key and use **Test connection** to verify it. A server-side `ASSEMBLYAI_API_KEY` can also supply the default credential. In **Create Post → Prepare content**, choose a clip and either enter a description, paste a transcript, or click **Transcribe clip audio**. ClipFlow uses FFmpeg to extract the audio from an analyzed MP4 up to ten minutes long and sends the audio to AssemblyAI after confirmation. When the transcript returns, review or edit it and click **Generate all content** or a field-specific Gemini action. AssemblyAI usage is subject to your account’s credits and plan. ClipFlow requests deletion of the remote transcript once it has collected the text. [AssemblyAI transcription API](https://www.assemblyai.com/docs/pre-recorded-audio/api-reference/transcripts/submit) · [AssemblyAI data retention](https://support.assemblyai.com/articles/2240096256-does-assemblyai-offer-zero-data-retention)

Local system settings cover queue concurrency, per-account and project allowances, missed times, the timezone for new drafts, and upload limits. Use `.env.local` for executable and storage paths and restart. Do not move a SQLite file or media directory without a backup and a planned migration.

## Credentials and backups

Saved settings take priority over environment variables. Clearing an integration also prevents fallback to those variables. OAuth credentials, API keys, and resumable secrets use AES-256-GCM with a fresh nonce. The server and worker share a stable master key at `data/database/.clipflow-private/master.key` by default, or use an explicitly configured 64-digit hexadecimal `TOKEN_ENCRYPTION_KEY`. The Windows key directory removes inherited access and grants the current user and SYSTEM; Unix uses owner-only modes. Keep the key separate from SQLite and outside Git, and restrict access to the machine account and backup.

With ClipFlow stopped, back up SQLite, user media, and the master key. For a restore, use the matching key before starting ClipFlow. A replacement key cannot decrypt old credentials or in-flight checkpoints; do not discard the old key until affected jobs are reconciled. If a key is lost, restore the matching backup or clear and reauthorize integrations after reviewing any possibly submitted jobs. Disconnecting deletes local authorization and cached analytics; revoke the app in the provider console if you also want to withdraw the provider grant.
